# 宿主接入

> 执行在 MCP 进程；**附着、审批、Overlay** 在桌宠（`stage-tamagotchi`）。

## 附着点

| 位置 | 作用 |
|------|------|
| `apps/stage-tamagotchi/src/main/services/airi/mcp-servers` | stdio MCP 管理（`McpStdioManager`） |
| 用户目录 `mcp.json` | 服务器清单；主进程校验/解析见 `shared/mcp-config.ts` |
| 主入口 `main/index.ts` | `setupMcpStdioManager` |
| 各窗 RPC | chat / settings / desktop-overlay / main 注入 MCP 服务 |

MCP 逻辑名常见为 `computer_use`（与 overlay 轮询名对齐）。

## Overlay 与坐标

| 文件 | 作用 |
|------|------|
| `renderer/pages/desktop-overlay.vue` | 叠层 UI |
| `desktop-overlay-polling.ts` | 轮询如 `computer_use::desktop_get_state` |
| `desktop-overlay-coordinates.ts` | MCP 返回框/点坐标系说明 |

叠层是**观察面**，不是另一套执行后端。

## 审批语义（桌宠）

| 作用域（产品意图） | 行为摘要 |
|--------------------|----------|
| `terminal_and_apps` | `terminal_exec` / open / focus：会话级可自动批后续同作用域 |
| `pty_session` | `pty_create`：**不**等同泛终端授权；不自动批「再开一个 PTY」 |

关键渲染侧：`renderer/modules/computer-use-approval.ts`，以及 `App.vue` 里对两种 scope 的区分。

改审批 UX 时：对照包内 `AGENTS.md`「Desktop approval semantics」四条 handoff，避免把 PTY 又并回旧的 `terminal_and_apps`。

## 与 Web / 通道的关系

- **偏 macOS + 桌宠**；不要默认 Web 能同等附着。
- **不是** `pnpm dev:server` Channel Hub；无 `server-sdk` announce。
- Twitter 的 `MCPAdapter` 是另一套「命令型 MCP」，勿与本执行基板混为一谈。
