# 终端泳道

> 当前 workstream 主线（terminal-lane-v2）。真相源：`services/computer-use-mcp/AGENTS.md` + `src/support-matrix.ts`。

## 已落地要点

1. **表面模型**：步骤可声明 `mode: 'exec' | 'auto' | 'pty'` 与 `interaction: 'one_shot' | 'persistent'`（`workflows/types.ts` · `surface-resolver.ts`）。
2. **`auto` 升级规则很窄**：已有绑定 PTY / 显式 persistent / 已知交互命令模式 / exec 失败出现交互标记 → 才升 PTY。
3. **Workflow 可 self-acquire PTY**：引擎内 `AcquirePtyForStep`、挂起点 `before_pty_acquire`；主线**不再依赖** harness 预创建 PTY。
4. **E2E 证明线**：`e2e-terminal-self-acquire`、`e2e-airi-chat-terminal-self-acquire`（聊天 demo 与服务层对齐）。

## 关键实现入口

| 文件 | 看什么 |
|------|--------|
| `src/workflows/engine.ts` | 步进、PTY 获取、挂起 |
| `src/workflows/surface-resolver.ts` | auto 规则 |
| `src/terminal/interactive-patterns.ts` | 交互命令/输出标记 |
| `src/bin/e2e-terminal-self-acquire.ts` | 服务层证明 |
| `src/bin/e2e-airi-chat-terminal-self-acquire.ts` | 桌宠聊天故事 |
| `src/support-matrix.ts` | `product-supported` vs `covered` |

Strict release gate 集合以包 `AGENTS.md` / `package.json` scripts 为准。

## 读代码时的四条自检（handoff）

改终端相关行为前/后，核对：

1. 主线是否仍是 **PTY self-acquire**（还是又依赖预创建）？
2. AIRI chat E2E 是否与服务层泳道对齐？
3. 桌宠审批是否区分 **`pty_session`** vs **`terminal_and_apps`**？
4. `support-matrix` 里哪些是 `product-supported`、哪些只是 `covered`？

## 刻意未扩面

在终端泳道未真正闭合前，包内政策：**不要**把 workstream 扩成浏览器 / 原生 click 产品化 / VS Code 产品化主线。那些工具面可以存在，但学习与贡献优先级让给终端。
