# 演示与用例入口

## 定位

回答两件事：仓内外**哪里能亲眼看到包在跑**；要不要单独建一个「用例仓库」。

| 入口 | URL / 命令 | 覆盖什么 |
|------|------------|----------|
| 产品 Web | https://airi.moeru.ai | 整端体验：舞台、聊天、设置（间接用满 Stage / UI / 音频等） |

## 本仓本地演示（优先）

| 命令 | 看到什么 |
|------|----------|
| `pnpm dev:ui` | 与线上 `/ui` 同系的 Histoire |
| `pnpm dev:web` | Web 端完整挂载 pages/layouts/stage-ui |
| `pnpm dev:tamagotchi` | 桌宠 + Electron 辅包 + 可内嵌 Channel |
| `pnpm dev:server` | Channel Hub（`server-runtime`） |
| `pnpm -F @proj-airi/stage-pocket …` | Pocket + `cap-vite` |
| Web/桌宠 **devtools** 路由 | 音频、动捕、窗口等实验面 |

组件调用实验壳：`apps/component-calling`（非主产品）。

## 要不要单独「用例仓库」？

**结论：现在不必新建外仓。**

理由：

1. **UI 面已经有官方 Histoire 站**（`/ui`），再建一套组件 demo 仓是重复维护。
2. **业务包强依赖 Pinia / Electron / Channel 宿主**，抽到外仓要么 mock 一半，要么再引一整棵 monorepo，ROI 低。
3. workspace 已声明 `examples/**`，若以后要补「可运行最小例」，优先在**本仓**加 `examples/<主题>`，用 `pnpm -F` 跑，而不是另开 Git 仓。
4. 学习侧用本域各组「怎么用」+ 包 README 片段即可覆盖「不改源码、只想会用」。

**何时再议外仓 / 本仓 examples：**

- 对外发 SDK（例如希望第三方只装 `@proj-airi/server-sdk` 就能抄作业）且文档站不够；或
- Histoire 无法承载的 **Node-only / Electron-only** 流程需要可 CI 的可运行例，且数量 ≥3 个稳定主题。

近期更值做的：把高频包 README「Usage」补齐，并在本 learning 域保持「怎么用」与演示链接同步（本次已加厚各组）。
