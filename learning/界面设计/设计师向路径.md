# 设计师向路径

> 面向 UI/UX：先建立气质与约束，再对关键画面，最后才碰工程分层。
> 工程向完整路径仍见 [学习路径](./学习路径.md)。

## 你要带走的三句话

1. **角色是主角，UI 是玻璃壳**——不要设计成 SaaS 仪表盘。
2. **Web 与桌宠同一套语汇，壳不同**——桌宠要为「透明 + 穿透 + 悬浮岛」单独想交互。
3. **主色是可调色相，不是固定品牌蓝**——稿子里预留 Hue / Dark，正文少用半透明糊对比度。

## 建议怎么「看」产品（比只读文档重要）

| 方式 | 做什么 |
|------|--------|
| 线上 / 本地 Web | 打开舞台首页：看角色占比、右侧聊天玻璃、顶栏轻重 |
| 设置 | `/settings` → 系统 → 常规 / 配色 / 场景：看信息密度与动效 |
| Histoire | `pnpm dev:ui`：Button、Field、色相滑条等原语态 |
| 桌宠（若有环境） | 主舞台穿透 + Controls Island 收起/展开 |

截图与结构标注见 [关键界面图鉴](./关键界面图鉴.md)。历史 UI 演进可翻 DevLog（如 `docs/content/zh-Hans/blog/DevLog-2025.03.10`、`DevLog-2025.03.20`）。

## 出稿检查清单（交付前）

- [ ] 第一眼是角色/舞台，不是表格或卡片墙
- [ ] 叠在角色上的控件用磨砂/半透明；**正文与标签仍够对比**
- [ ] 圆角与间距贴近规范表（岛 `rounded-xl`，按钮常用 `rounded-lg`）
- [ ] 图标偏 Solar bold-duotone，避免杂乱多套风格混用
- [ ] 标明 Light / Dark；主题色用「色相可变」而不是锁死 hex 品牌色
- [ ] 若含桌宠：画了透明窗、穿透时「可点区」、Controls Island
- [ ] 空状态 / 加载 / 错误至少有一版意图（见体验要点）

## 不要一上来做的事

- 不要先做完整 Design Token 文件再去「套」产品——本仓 token 是 **Uno + Chromatic 运行时**，以现网语汇对齐更稳
- 不要把设置页做成 Ant Design 密表；设置是 **插画感入口卡片 + 分区 Section**
- 不要假设桌宠 = 缩小版 Web 首页（聊天往往在独立窗）
