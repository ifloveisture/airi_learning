# 体验要点

> 产品定位：数字伴侣 / 虚拟角色舞台（意象接近 Neuro-sama 一类容器），不是效率工具后台。

## 设计原则

| 原则 | 含义 | 违反时的样子 |
|------|------|----------------|
| **舞台优先** | 角色与场景占视觉权重；UI 让路 | 首屏被设置项、统计条、多卡片占满 |
| **壳轻核心重** | 控件像玻璃浮层；对话与角色是核心任务 | 厚重实心面板挡住模型 |
| **同一语汇，分端形态** | 色、字、圆角、图标跨端一致；布局按端变 | 桌宠另起一套扁平 Material |
| **可换色可 Dark** | 用户可调 Hue / 动态色相 / 深浅色 | 稿死锁单一品牌蓝且无 Dark |
| **动效有戏但不挡事** | 转场、Ripple、入场可活泼；设置里可关过渡 | 动画拖慢操作或眩晕 |

## 关键用户任务（UX 骨架）

```text
打开舞台 → 看角色 / 换背景
        → 打字或语音聊天
        →（可选）换角色卡 / Provider / 语音
        → 进设置调主题、模型、场景
```

| 任务 | Web | 桌宠 |
|------|-----|------|
| 看角色 | 首页中央 `WidgetStage` | 透明置顶窗中央 |
| 聊天 | 右侧（或移动端底部）磨砂区 | **独立 Chat 窗**；主舞台偏展示 |
| 快捷操作 | Header / Chat 动作按钮 | **Controls Island**（悬停展开，闲置收起） |
| 点「空白」 | 无特殊 | 可能 **穿透到桌面**；只有角色命中区与岛可点 |

设计桌宠时必须回答：**用户怎么知道现在能不能点角色？穿透开时岛是否仍可达？**

## 信息架构（设置）

设置总览是 **纵向入口列表**（RippleGrid + IconItem），不是侧栏多级树一次摊开：

```text
/settings
  ├─ 角色 / 模块 / 提供商 / …（由路由 meta.settingsEntry 聚合）
  └─ 系统
       ├─ 常规（含 Dark、过渡、桌宠岛图标尺寸等）
       ├─ 配色（Hue、动态、主题预设）
       └─ …
  └─ 场景（背景图库等）
```

入口卡片：图标（Solar duotone）+ 标题 + 短描述；大号水印图标可出现在页角（装饰，不抢点击）。

## 可读性与半透明

官方工具章 + 实装共识：

- **改色度**：优先实色阶，少用 alpha「调淡」冒充色板。
- **磨砂壳**：`bg-*/50` + `backdrop-blur-md` 用于叠角色；**标签 / 正文**用 `text-sm`/`text-xs` + `neutral-500` 等实色字。
- Dark：同类组件必须有 `dark:` 对；设置 layout 会改浏览器 `theme-color`。

验收：把聊天面板叠在浅色与深色角色图上各看一眼，正文是否仍可读。

## 状态与反馈（设计时应覆盖）

| 状态 | 产品里常见做法 | 设计注意 |
|------|----------------|----------|
| 加载 | 桌宠舞台有半透明 loading；按钮 `loading` + spinner | 勿用不透明全屏挡住角色太久 |
| 禁用 | `opacity-50` + `cursor-not-allowed`（Button） | 保持外形，降低存在感 |
| 悬停 / 按下 | primary/neutral 透明度阶梯（见视觉规范） | 磨砂按钮用「透明度变化」多于重阴影 |
| 焦点 | `focus:ring-2` | 键盘可达时不要去掉环 |
| 空聊天 | 历史区空 + 输入仍在 | 可轻提示，勿大空状态插画抢角色 |
| 穿透开启 | fade-on-hover、notice 页说明 | 需要「模式可见」：岛上开关或短暂提示 |
| 错误 | `ErrorBoundary` / Callout 一类 | 用语义色（红/琥珀），仍保持圆角语汇 |

## 动效体验

| 场景 | 期望 |
|------|------|
| 进设置分区 | 轻微上移淡入（`v-motion`，错落入场） |
| 设置总览点击 | Ripple 扩散再跳转（可关） |
| Web 路由 | 可选舞台转场（如 bubble-wave-out） |
| 桌宠岛 | ~1.5s 无操作收起；展开要快 |

原则：**活泼、可读、可关**。长时操作不要只靠装饰动画。

## 无障碍（底线）

仓内未写成完整 a11y 专章；出稿至少：

- 图标按钮有可见或 sr 可理解的含义（title / aria）
- 对比度：正文对面板底达到可读（半透明底上测 Dark/Light）
- 不要把关键操作只放在 hover 才出现且无法键盘聚焦的控件上（桌宠岛例外需另给等效入口，如托盘/快捷键——产品侧已有托盘等，设计勿唯一依赖悬停）

## 禁止清单（速查）

1. 首屏仪表盘化（多 KPI、密表、多卡片墙）
2. 实心灰白后台风压过角色
3. 桌宠做成「浏览器窗口缩小贴」而无穿透/岛逻辑
4. 固定死唯一品牌色、忽略用户配色与 Dark
5. 新图标集与 Solar duotone 混搭无理由
6. 大面积 `backdrop-filter` + 低对比浅字
