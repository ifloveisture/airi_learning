与 Discord「桥」不同：Telegram / Satori 跑 **进程内 LLM loop**，**不**经 `server-sdk`。
`services/` 不全在本域 → [services全景](./services全景.md)。
学 Channel → [通道机器人](../通道机器人/)。

## 对比（核心三角）

| 维度 | Discord（通道） | Telegram | Satori |
|------|-----------------|----------|--------|
| 文档域 | [通道机器人](../通道机器人/) | 本域 | 本域 |
| Channel | **是** | **否** | **否** |
| 认知 | Stage | 进程内 Agent | 临时 Mini-Core |
| 持久化 | Stage 会话 | Postgres + pgvector | PGlite |
| 适合学 | Channel 闭环 | Agent loop / DB / OTel | Adapter + 合并叙事 |

## 同构模型（仅 TG ≈ Satori）

```text
平台事件 → 去重队列 → unread → handleLoopStep
  → imagineAnAction(JSON) → dispatch → 续跑 / 周期 tick
```

Minecraft 虽也有进程内认知，但经 Channel 回 Stage，且 Mineflayer 路径弃用中 → 见 [游戏与操控](../世界接入/游戏与操控.md) · [迁移背景](../世界接入/Minecraft迁移背景.md)，勿与上图硬套。

## 对照句

- **Discord** = Channel 感官，大脑在 Stage
- **Telegram** = 独立生命（重：向量 / OTel / 多模态）
- **Satori** = 独立生命（轻：协议 / 临时 Core）
- **其余 services** = 先查 [services全景](./services全景.md)
