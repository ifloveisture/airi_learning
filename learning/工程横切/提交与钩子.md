# 提交与钩子

## 定位

本仓 `git commit` **不慢在写对象**，慢在 **pre-commit 必跑 lint 自动修复**。学习笔记也要过同一套钩子。Windows 上若暂存含**中文路径**，还要先保证终端是 **UTF-8**，否则钩子会「看起来像挂了 / 报错莫名」。

## 真源

| 项 | 路径 / 配置 |
|----|-------------|
| 钩子安装 | 根 `package.json` → `postinstall`: `pnpm exec simple-git-hooks` |
| pre-commit | `simple-git-hooks.pre-commit` = `pnpm nano-staged` |
| 暂存过滤 | `nano-staged`: `"*": "moeru-lint --fix"`（**所有**暂存文件） |
| 上游文案约定 | 根 `AGENTS.md` PR / Workflow：Conventional Commits；**禁止 gitmoji** |

## 一次 commit 实际发生什么

```
git commit
  → simple-git-hooks / pre-commit
  → pnpm nano-staged
  → 对每个暂存文件跑 moeru-lint --fix
  → 通过才真正写入 commit；失败会还原 staging 侧补丁（改动通常还在）
```

因此：

- 只改几个 `.md` / `.yaml` 也会触发 lint（规则匹配到的才有效检查，但进程仍会起）。
- 暂存文件多、冷启动时体感可达一两分钟；以钩子最终 × / √ 为准，不要只看最后一行 `0 errors` 摘要。

## Windows · 中文路径 · UTF-8（本机已踩过）

`learning/` 下大量中文目录名。PowerShell / cmd **默认代码页不是 UTF-8** 时，`nano-staged` 传给 `moeru-lint` 的路径会乱码（例如 `界面设计` → `界面���计`），钩子失败或空转很久——**不一定是 message 写错，也不一定是真 lint**。

本机已验证可用的提交前设置（PowerShell）：

```powershell
chcp 65001 | Out-Null
$OutputEncoding = [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
$env:LANG = 'C.UTF-8'
$env:LC_ALL = 'C.UTF-8'
```

然后再 `git add` / `git commit`。单测钩子也可：

```powershell
# 先切 UTF-8，再对含中文路径的文件跑
pnpm exec moeru-lint --fix -- 'learning/界面设计/体验要点.md'
```

过了 UTF-8 仍失败时，再查**真实 lint**（如 `console.log`、`no-new` 等），与编码问题分开处理。

## 怎么少踩坑

| 做法 | 说明 |
|------|------|
| 先 UTF-8 | 含中文路径的 commit：先 `chcp 65001` + UTF-8 OutputEncoding（见上） |
| 提交前自检 | `pnpm exec moeru-lint --fix -- <paths>` |
| 缩小暂存面 | 无关文件别 `git add -A`；学习笔记与产品代码可拆两次 commit |
| 失败后 | `git status`：常见是仍 staged、无新 commit；修完再 commit，**不要**默认 `--no-verify` |
| 跳过钩子 | 仅当用户明确要求；本学习库默认不跳 |

## 提交说明（message）约定

| 来源 | 要求 |
|------|------|
| 上游 `AGENTS.md` | Conventional Commits，如 `feat(stage-ui): …`；禁止 gitmoji |
| 本学习库本地习惯 | 可用中文序号列表（`1. …` / `2. …`），动词开头、一条一改动点 |

给上游开 PR 时优先跟 **AGENTS / 仓库惯例**；纯 `learning/` 本地笔记可用中文序号。中文 message 在 UTF-8 终端下更稳。

钩子已启用。慢主要来自 **全量 `*` + lint:fix**；Windows 上偶发失败优先怀疑 **路径编码**，其次才是真 lint。

## 边界

- **CI lint / typecheck / test**：发 PR 后的门禁，见《测试与质量门禁》《发布与CI地图》；不等于本地 pre-commit 的全部范围。
- **Crowdin / 文案键**：改 YAML 的流程见《文案与Crowdin》，与钩子正交。
