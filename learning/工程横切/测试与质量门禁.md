# 测试与质量门禁

## 定位

贡献代码时的默认验收：定向 Vitest → 包级 typecheck → 根 lint。根 `vitest.config.ts` 用 **projects** 聚合若干工作区，并非每个包都挂在根上。

## 真源

| 项 | 路径 |
|----|------|
| 根 Vitest | `vitest.config.ts`（projects：server、ui-server-auth、stage-tamagotchi、core-agent、plugin-sdk*、server-runtime/sdk、scenarios-* 等） |
| 约定 | 根 `AGENTS.md` Testing / Commands |
| 包内配置 | 各包可自有 `vitest.config.ts`（如 `stage-ui`） |

## 跟读

1. 打开根 `vitest.config.ts`，看 `test.projects` 列表
2. 找你要改的包是否在列表中；若不在，用该包自己的 vitest 或 `pnpm -F … exec vitest`
3. 读邻近 `*.test.ts` 的 mock 风格（IPC 用 `vi.fn`，勿起真 Electron）
4. 跑一条定向测试确认绿

## 命令

```bash
# 单文件（最快）
pnpm exec vitest run path/to/file.test.ts

# 某工作区全部
pnpm -F @proj-airi/stage-tamagotchi exec vitest run

# 根聚合（慢，看 projects 是否包含目标）
pnpm test:run

pnpm -F @proj-airi/stage-ui typecheck
pnpm lint
pnpm lint:fix
```

## 现状

已实现；CI 走 lint/typecheck/test 相关 workflow。浏览器模式 Vitest、Playwright 用于部分场景，按包文档启用。

## 边界（写在本页即可）

- **Histoire / Devtools**：看组件故事与运行时调试页，不替代单测。
- **apps/server verifications**：`apps/server/docs/ai-context/verifications/` 是服务端证据链笔记，不是 Vitest 替代。
- **不要**为了测私有实现去改 `exports` 或绕过包边界（AGENTS）。
- **`git commit` 变慢 / 钩子失败**：见 [提交与钩子](./提交与钩子.md)（`nano-staged` → `moeru-lint --fix`）。
