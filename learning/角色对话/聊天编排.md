# 聊天编排

## 职责拆分

聊天不是单一 `useChatStore`，而是编排器 + 多个子 store：

| Store | 文件 | 职责 |
|-------|------|------|
| `useChatOrchestratorStore` | `packages/stage-ui/src/stores/chat.ts` | 产品入口：`ingest` / `ingestOnFork`；对接 core-agent |
| `useChatSessionStore` | `stores/chat/session-store.ts` | 会话 ID、消息表、fork、IDB、云同步 outbox |
| `useChatStreamStore` | `stores/chat/stream-store.ts` | 前台 `streamingMessage`；begin / append / finalize |
| `useChatContextStore` | `stores/chat/context-store.ts` | 运行时上下文桶（`createContextRegistry`，上限约 400） |
| `useChatMaintenanceStore` | `stores/chat/maintenance.ts` | 聚合清理：消息 + 上下文 + 取消发送 + 重置流 |

另：`stores/chat/hooks.ts`（钩子）、`context-prompt.ts`（再导出 core-agent prompt helpers）。

内核：`packages/core-agent/src/runtime/chat-orchestrator-runtime.ts`
`createChatOrchestratorRuntime` → FIFO 队列 → compose → stream → 落库 / telemetry。

判定常数（generation 作废、上下文 400 等）→ [算法主线/编排与上下文](../算法主线/编排与上下文.md)。

## 主流程

```text
UI 发消息
  → ingest({ … })
  → core-agent 入队（FIFO）
  → appendSessionMessage(user)     # 先落用户消息
  → useLLM().stream / streamWithStageAdapters
  → foregroundStream.patch         # 刷新 streamingMessage
  → appendSessionMessage(assistant)
  → persistSession → chatSessionsRepo（IndexedDB）
  →（可选）pushMessageToCloud / outbox
```

模型来源：`useConsciousnessStore` 的 `activeProvider` / `activeModel`，实例经 `useProvidersStore().getProviderInstance`。

## `sendSource`（易混）

| 条件 | telemetry `sendSource` |
|------|------------------------|
| `options.input` 有值 | `'voice'` |
| 否则 | `'text'` |

本地麦克风 → STT → `ingest(text)` 的路径**常常不传** `options.input`，因此可能记成 `'text'`。
经 Channel 桥（如 `context-bridge` 的 `input:text`）带 `options.input` 时才标 `'voice'`。
学语音产品链路时以 [听力转写](../语音交互/听力转写.md) 为准，不要只信字段名。
