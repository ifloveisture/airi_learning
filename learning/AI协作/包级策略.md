# 包级策略

## 定位

少数包/服务在目录内自带 `AGENTS.md`：比根指南更贴近**当前 workstream**，有的还写明**多 Agent 怎么分工**。改这些目录时，包内文件是 handoff 真源。

## 真源

| 包 / 服务 | 路径 |
|-----------|------|
| computer-use MCP | `services/computer-use-mcp/AGENTS.md` |
| MediaPipe 动捕驱动 | `packages/model-driver-mediapipe/AGENTS.md` |

（以仓库实存为准；新增包级指南时补本表。）

## 跟读

1. 确认任务路径是否落在上表目录
2. 先读该文件顶部 Mission / Intent / Collaboration Policy
3. 有 Status Snapshot 的：用快照续工，**不要**靠聊天摘要
4. 改完行为后按文件内 Handoff Rules 回写快照

## `computer-use-mcp`：协作策略摘要

文件明确写了：策略**仅限本包**，不要抄进根 `AGENTS.md`（其它包风险画像不同）。

默认形态（文内用语）：**GPT-5.5 Controller + Spark / mini 只读 Worker 池**。

要点（读原文细节）：

| 角色 | 职责边界 |
|------|----------|
| 主控（文中 GPT-5.5） | 问题边界、冲突证据裁决、落补丁、验收命令、最终判断 |
| Spark / mini | 只读并行：探路径、找测试缺口、看 diff、分诊 CI、拆 PR 规划 |
| GitHub Copilot | **外部** worker：评审、候选 PR、文档清理；合并前须主控核对 |
| Gemini CLI | 本地大上下文评审 / 日志分析；**勿与 Codex 同 worktree 并发写** |

其它硬约束（摘要）：

- Spark 结论须带路径与证据；无证据当猜测
- 测试与运行日志压过模型口述
- `.codex/`、Copilot 治理文件、业务运行时改动：**分 PR / 分 commit**
- 报告清单：改了哪些文件、精确测试命令、exit code、残留风险

Status Snapshot 专管 **terminal-lane-v2** 等主线事实（PTY self-acquire、approval 语义、`support-matrix` 状态）。续工顺序见文内「Where To Look First」。

产品学习侧入口：[本机操控/学习路径](../本机操控/学习路径.md)。

## `model-driver-mediapipe`：风格便签

更短，偏实现约定：

- 实验性单人动捕管线（stage-web devtools）
- 偏好 FP / factory；MediaPipe 细节关在 `src/backends/`
- `src/types.ts` 为对 stage 的契约；新字段宜可选
- `detectForVideo` 同步 → 引擎用丢帧 / hz 限流

无多 Agent 分工段落——需要时只当包内风格与关键文件索引。

## 与根指南的关系

```text
根 AGENTS.md          → 全仓默认
包内 AGENTS.md        → 覆盖本目录的 handoff / 更严协作策略
Skill                 → 技术主题（Eventa、Vue…），不替代包 handoff
```

包内政策写「不要提升为全局规则」时，遵守——例如 computer-use 的多 Agent 编制。

## 现状

| 项 | 说明 |
|----|------|
| 包级文件数量 | 少；高质量 handoff 集中在 computer-use |
| 根目录 `.codex/` | 当前不存在；策略文仍要求「配置改动与业务 PR 分离」 |

## 边界

| 是 | 不是 |
|----|------|
| 目录级 Agent 操作手册 + 续工快照 | 产品功能说明书的唯一来源（仍要对照 README / 测试 / 源码） |
| computer-use 多 Agent 编制 | 全仓强制编制 |
| MediaPipe 包备注 | 舞台呈现全域规范 |
