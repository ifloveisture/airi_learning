# 根指南

## 定位

仓库级「给 Agent / 贡献者的总则」。几乎所有编码 Agent 都会先碰到它；细主题再下钻到 Skill 或 `docs/ai*`。

## 真源

| 项 | 路径 |
|----|------|
| 主指南 | `AGENTS.md`（仓库根） |
| Claude 入口 | `CLAUDE.md` → 内容仅为 `@AGENTS.md` |
| 服务端入口 | `apps/server/CLAUDE.md` |

## 跟读

1. 打开根 `AGENTS.md`，只扫 `##` 标题建立地图
2. 按任务跳进对应章节（不必通读）
3. 若在 `apps/server`：再读 `apps/server/CLAUDE.md` 的 Overview / Key Design Decisions

## `AGENTS.md` 章节地图

| 章节 | Agent 用它做什么 |
|------|------------------|
| Tech Stack (by surface) | 认清 Web / 桌宠 / 移动 / 共享包各自栈 |
| Structure & Responsibilities | apps / stage-ui / Eventa / injeca / CI / Uno 职责 |
| Key Path Index | 「某能力在哪个路径」速查 |
| Commands (pnpm with filters) | `-F` typecheck / vitest / lint / build |
| Development Practices | 边界、Valibot、Eventa、错误信息、禁止无脑兼容补丁 |
| Styling & Components | class 数组写法、Uno、`@proj-airi/ui`、更新 `ui-components.md` |
| Testing Practices | 先复现再改；tracker id；勿假 mock 绕过导入问题 |
| TypeScript / IPC / Tools | 契约归属、禁止乱改 tsconfig 掩盖错误、环依赖当设计问题 |
| i18n / CSS/UNO | 文案进 `packages/i18n`；样式进 `uno.config.ts` |
| Readability, Naming, Comments | `NOTICE`/`TODO`、fallback/协议注释；**TS 命名（文件/符号/类型/API）**见 [工程横切/TypeScript命名](../工程横切/TypeScript命名.md) |
| Module Design | 深模块、忌空壳 service、忌为测试强行导出 |
| PR / Workflow Tips | Conventional Commits、**禁止 gitmoji**、新依赖先问用户 |
| TypeScript Coding Regulations | JSDoc、workaround 格式、normalizer 文档、测试 ROOT CAUSE 块 |
| Readability Review Checklist | 复杂模块自检 |

## `CLAUDE.md` 与多工具入口

| 文件 | 角色 |
|------|------|
| 根 `CLAUDE.md` | Claude Code 惯例入口；本仓刻意做成**单行引用** `AGENTS.md`，避免双份维护 |
| `apps/server/CLAUDE.md` | 服务端专用摘要：部署模型（Railway 多实例）、分层、Flux 读写分离、LLM 路由、并**强制**改前读 `docs/ai-context/` |

Cursor 侧会通过 workspace rules 注入根 `AGENTS.md`（以及本机 User Rules）；**不要**假设每个工具都自动加载 `.agents/skills`——相关任务应主动打开对应 `SKILL.md`。

## 现状

根指南与 server CLAUDE 活跃；根 `CLAUDE.md` 保持极薄是刻意设计。

## 边界

- **工程横切专题**：抽「测试 / 提交 / CI / Eventa」贡献闭环，不替代通读 `AGENTS.md`。
- **包级 `AGENTS.md`**：可覆盖更严的协作策略与 handoff；见 [包级策略](./包级策略.md)。
- **不要**在 learning 里维护第二份「完整 AGENTS」。
