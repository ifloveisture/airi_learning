## 定位

除了根指南与 Skills，仓里还有几套**给 Agent 长期查阅**的 Markdown：组件契约、服务端架构、排障案例、（可选）验证自动化设计。

## 跟读

1. 先分清三套目录的受众（下表）
2. 云端任务：走 [云端服务/ai-context导读](../云端服务/ai-context导读.md) 选篇
3. UI 原语：直接打开 `ui-components.md`
4. 排障：按 [Solutions用法](../工程工具/Solutions用法.md) 搜 frontmatter

## 三套目录怎么选

| 目录 | 写给谁 | 典型问题 |
|------|--------|----------|
| `docs/ai/context/ui-components.md` | 改 `@proj-airi/ui` 的人 / Agent | props / slots / emits 契约；**改组件须同步改此文**（`AGENTS.md` 明文要求） |
| `docs/ai/context/verification-automation.md` | 设计 verification 自动化的人 | 设计稿，**未实施**；解释如何把 `verifications/` 从人工贴输出推进到可执行 evidence |
| `docs/ai/context/plans/` | 设计决策存档 | 如角色卡云同步设计笔记 |
| `apps/server/docs/ai-context/` | 改云端的人 / Agent | 装配、路由、Flux、Auth、Redis、OTel、verification 证据 |
| `docs/solutions/<category>/` | 排障时 | 「这类坑以前怎么修」；篇数少，有一篇算一篇 |

## server `ai-context`（只记地图）

入口：`apps/server/docs/ai-context/README.md` 与 `apps/server/CLAUDE.md`。

面向四个问题（README 原话摘要）：

1. 怎么启动和组装
2. API / WS 落到哪个服务
3. 谁以 Postgres 为准、谁是缓存
4. 计费等高风险链路的约束

细篇索引与「按问题选文」见云端域导读，**本域不复抄篇名长表**。

相关：根仓还有一份 `docs/ai/context/verification-automation.md`，讨论如何把 server 下 `verifications/` 的人工步骤机器化——与 ai-context 内已有 verification 文档配套，但自动化本身尚未实施。
