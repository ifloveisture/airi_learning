# 配置分层

## 定位

把仓内「给 Agent 看的东西」按**作用半径**排成层，避免把根指南、Skill、包 handoff、云端 ai-context 混成一坨。

## 真源

| 层 | 典型路径 |
|----|----------|
| 根指南 | `AGENTS.md` · `CLAUDE.md` |
| 应用 / 服务入口 | `apps/server/CLAUDE.md` · 包内 `AGENTS.md` |
| Skills | `.agents/skills/*/SKILL.md` |
| Cursor 斜杠命令 | `.cursor/commands/*.md` |
| 仓库级 AI 上下文 | `docs/ai/context/` |
| 服务端权威上下文 | `apps/server/docs/ai-context/` |
| 排障案例 | `docs/solutions/` |
| GitHub agentic | `.github/agents/` · `.github/workflows/*.md`（gh-aw） |

## 跟读

1. 先认「根 → 目录 → Skill → 专题上下文」四步
2. 用下表对号入座当前任务
3. 冲突时：**包内 AGENTS / ai-context / 源码** 压过 learning 摘要

## 分层一览

```text
┌─ 工具专属入口（薄）
│    CLAUDE.md              → 仅 @AGENTS.md
│    apps/server/CLAUDE.md  → 服务端摘要 + 指向 ai-context
│    .cursor/commands/      → 人工触发的斜杠命令（如 deslop）
│
├─ 全局贡献约定（厚）
│    AGENTS.md              → 栈、路径、命令、测试、模块设计、TS 规章
│
├─ 按任务加载的能力包
│    .agents/skills/        → Vue / UnoCSS / Eventa / xsAI / 浏览器自动化 …
│
├─ 按目录收紧的 handoff
│    packages/*/AGENTS.md
│    services/*/AGENTS.md   → 现状快照 +（可选）多 Agent 协作策略
│
├─ 按主题的权威长文
│    docs/ai/context/                 → UI 组件 API、验证自动化设计稿
│    apps/server/docs/ai-context/     → 云端装配 / 计费 / Auth / verification
│    docs/solutions/                  → 排障案例（篇数少）
│
└─ CI / 仓库自动化侧的 Agent
     .github/agents/agentic-workflows.agent.md
     .github/workflows/pr-triage.md   → Copilot 引擎的 PR 分诊（gh-aw）
```

## 读什么：按任务速查

| 你在做 | 先读 |
|--------|------|
| 任意改码、不知道约定 | 根 `AGENTS.md` 对应章节（测试 / 样式 / 模块设计 …） |
| Vue / Pinia / Router | skill `vue` + `vue-best-practices`（必要时 `vueuse-functions`） |
| UnoCSS class | skill `unocss` + 根 `uno.config.ts` |
| Eventa / IPC | skill `eventa` + `apps/stage-tamagotchi/src/shared` |
| xsAI / `@xsai/*` | skill `xsai` |
| 改 `packages/ui` 组件 | `docs/ai/context/ui-components.md`（改完要同步更新） |
| 改 `apps/server` 高风险链路 | `apps/server/CLAUDE.md` → `docs/ai-context/` 相关篇 |
| 重构 server 网关路由 | skill `server-gateway-refactor` |
| 桌宠 Electron 自动化 | `agent-browser` + `agent-browser-electron` |
| Godot C#（引擎目录内） | `stage-tamagotchi-godot-csharp` |
| computer-use / 终端泳道 | `services/computer-use-mcp/AGENTS.md`（handoff 真源） |
| 写英文 release notes | skill `release-note-writer` |
| 清本分支 AI 废话 diff | `.cursor/commands/deslop.md` |
| 查是否修过同类坑 | `docs/solutions/`（按 frontmatter 搜） |

## 「优先级」怎么理解

没有单一 YAML 声明全局优先级；实践上：

1. **用户当次指令** > 一切
2. **当前目录包级 `AGENTS.md`**（若存在）> 根指南里的泛化描述
3. **权威专题文**（`ai-context`、`ui-components`）> learning 摘要
4. **Skill** 在相关任务时应加载；与根指南冲突时，以**仓内事实与包边界**为准
5. learning 笔记只做导航，不替代原文

| `.codex/` | 本仓**无**根级 `.codex/`（computer-use 策略文提到配置应与业务 PR 分离） |

## 边界

| 是 | 不是 |
|----|------|
| 贡献者 / Agent 协作约定 | 产品「角色卡 / 聊天编排」功能说明 |
| 仓内 Skills | Cursor 本机 User Rules（Obsidian 协作等） |
| server `ai-context` | VitePress 用户手册 `docs/content/.../manual/` |
