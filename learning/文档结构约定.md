# 文档结构约定

## 目标

每个**小专题**应能单独顺着研究下去；跨域链接尽量留在 **README / 学习路径 / 角色入口**，少写在专题正文。

## 专题正文结构（推荐）

1. **定位**（1–3 句）
2. **真源**（路径表）
3. **跟读**（3–6 步，只点本主题文件）
4. **命令 / env**（若有）
5. **现状**（已实现 / 可启用 / 进行中）
6. **边界**（邻近概念用短表写清「不是什么」，**不必** `→ [其它域/xxx](…)`）

## 允许的链接

| 位置 | 可以链 |
|------|--------|
| 域 README、学习路径 | 域内专题；少量「总索引」 |
| 专题正文 | 同域其它篇；仓内源码路径；`apps/server/docs/ai-context/` 等权威外置文 |
| 专题正文 | **少**链到其它功能域学习文 |

## 减少互引的做法

- 需要背景时：**复制 2–4 行边界**，而不是「详见某某域」。
- 算法阈值与功能读码分开：算法主线写规则，功能域写包路径；两边边界段各写一句即可。
- 世界接入不再当「纯跳板」：竖切文自带启动与边界。

## 刻意薄写

维护在总索引 [薄写与缺口](./薄写与缺口.md)。新增「故意不写」必须登记，避免被当成文档债遗忘。
