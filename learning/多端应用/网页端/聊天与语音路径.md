# 聊天与语音路径（Web）

Web 上文字与语音最终都进聊天编排；语音主路径已统一到 `useVoiceStore`，不再分「流式麦 / 首页 VAD」两套旧链路。

## Web 与桌宠对照（读码前）

两端共用 `stage-ui` 编排与 Voice / Speech；差在壳与多窗。

| 点 | Web（`stage-web`） | 桌宠（`stage-tamagotchi`） |
|----|--------------------|----------------------------|
| 文字入口 | `stage-layouts` 的 `InteractiveArea` / `ChatArea` → 直接 `ingest` | 同款布局组件；跨窗时 follower 经 **chat-sync** `requestIngest` → **authority** 窗执行 |
| 聊天权威 | 单页单编排 | 主舞台 `/` 为 authority；`/chat` · `/spotlight` 为 follower |
| 听入 | `useVoiceStore` + Hearing 设置 | 同核；多窗时麦归属冲突会 cancel 他窗 input |
| TTS / 口型 | `Stage.vue` 挂编排钩子 | 同；主舞台页嵌 Stage，follower 聊天窗主要跟气泡 |
| 开窗 / 穿透 | 无 | Eventa（与 chat-sync 分工：开窗走 Eventa，气泡一致走 sync） |

桌宠多窗细节见同域上一级 [桌宠端/多窗同步](../桌宠端/多窗同步.md)。下面两节以 Web 文件路径为主；桌宠跟读时把 `ChatArea` 换成本端 `InteractiveArea` 即可。

## 文字发送

```text
InteractiveArea.vue
  └─ ChatArea.vue
       handleSend()
         → providersStore.getProviderInstance(activeProvider)
         → useChatOrchestratorStore().ingest(text, { chatProvider, model, providerConfig })
              └─ packages/stage-ui/src/stores/chat.ts
                   └─ core-agent runtime.ingest(...)
```

| 文件 | 角色 |
|------|------|
| `packages/stage-layouts/.../InteractiveArea.vue` | 桌面布局右栏 |
| `packages/stage-layouts/.../ChatArea.vue` | 输入框、发送、语音控件 |
| `packages/stage-layouts/.../MobileInteractiveArea.vue` | 移动端同样 `ingest` |
| `packages/stage-ui/src/stores/chat.ts` | 编排入口 |
| scenarios `ChatHistory` 等 | 气泡与会话抽屉 |

模型来自 `useConsciousnessStore` 的 active provider/model。细节见 [聊天编排](../../角色对话/聊天编排.md)。

## 语音输入（Hearing → Voice）

```text
麦 / HearingConfig（inputMode）
  → useVoiceStore（VAD · 唤醒 · 句末 · 改写 · 可选说话人）
  → hearing.createTranscriber()
  → 草稿 / inlay / auto-send
  → 聊天 ingest（spoken turn 可挂 composer tools）
```

| 文件 | 角色 |
|------|------|
| `stage-ui/stores/modules/hearing.ts` | Provider、模式、auto-send、句末/改写开关 |
| `stage-ui/stores/voice.ts` | 听入生命周期与插件装配 |
| `scenarios/chat/.../voice-input-button.vue` | 麦按钮与模式文案 |
| `Stage.vue` | 连接 voice host / 输出 |

模式与设置拆页 → [听力转写](../../语音交互/听力转写.md)。未配 STT 时 Web 仍可能走浏览器 Web Speech 等 provider 策略（以 `hearing` store 为准）。

## TTS 输出（舞台）

回复朗读不在 ChatArea 文本框逻辑里，而在 `Stage.vue`：Voice / Speech 管线 → TTS provider。见 [语音合成](../../语音交互/语音合成.md)。

## 建议动手验证

1. `pnpm dev:web`，配好 LLM + Hearing Transcriber
2. 打字发送，在 Vue DevTools 看 chat / session store
3. 切换 `always-on` / PTT / `wake-word`，确认只有对应条件开输入
4. （可选）注册声纹并打开说话人识别，看 trace 是否记分
