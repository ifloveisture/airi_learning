# 多窗同步

> 桌宠有多窗口、多 Renderer；聊天状态用 **BroadcastChannel** 同步，不是 Eventa。

## 通道

| 项 | 值 |
|----|-----|
| Store | `src/renderer/stores/chat-sync.ts` |
| Lifecycle | `src/renderer/stores/chat-sync-lifecycle.ts`（在 **`App.vue` 根**初始化） |
| Channel 名 | `airi:stage-tamagotchi:chat-sync` |

页面卸载 **不应** dispose channel（窗内路由切换会卸页，窗还在）。角色在窗口生命周期捕获。

## 角色（按初始路由）

`resolveChatSyncWindowRole`：

| 路由 | 角色 | 含义 |
|------|------|------|
| `/` | **authority** | 主舞台：会话权威，广播 snapshot / 响应命令 |
| `/chat` · `/spotlight` | **follower** | 跟读 / 请求 ingest，保留部分本地活跃会话策略 |
| `/settings` · `/settings/*` | **client** | 设置侧轻量参与 |
| 其它 | 不启 sync | 如 caption / overlay 等 |

初始路径解析会优先看 **`location.hash`**（主窗可能无 hash，落到 `/`）——见 `resolveInitialChatSyncRoutePath`。

## 谁在用

| 消费者 | 路径 |
|--------|------|
| 主舞台 | `pages/index.vue` |
| 交互区 | `components/InteractiveArea.vue` |
| Spotlight | `pages/spotlight.vue` |

产品入口仍是 `useChatOrchestratorStore().ingest`（内核见 [角色对话/聊天编排](../../角色对话/聊天编排.md)）；跨窗时 follower 经 sync **请求** authority 侧 ingest，而不是每个窗各自为政写一套编排。

## 与 Eventa 的边界

| | chat-sync | Eventa |
|--|-----------|--------|
| 传输 | 同应用多 Renderer 的 BroadcastChannel | Main ↔ Renderer IPC/RPC |
| 典型载荷 | 会话/流式快照、ingest 请求 | 开窗、穿透、MCP、更新、插件… |

开「聊天窗」本身走 Eventa（如 `electronOpenChat`）；窗开起来之后的 **聊天气泡一致性** 走 chat-sync。

## 阅读顺序

1. `chat-sync-lifecycle.ts`（角色表）
2. `chat-sync.ts` 里 `initialize(role)` / authority 广播
3. `App.vue` 如何挂 lifecycle
4. `spotlight.vue` 或 `InteractiveArea.vue` 一次 `requestIngest` 调用链
