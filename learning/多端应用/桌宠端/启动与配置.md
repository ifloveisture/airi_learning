# 启动与配置

> 包：`@proj-airi/stage-tamagotchi` · 配置：`apps/stage-tamagotchi/electron.vite.config.ts`

## 双进程入口

| 进程 | 路径 | 说明 |
|------|------|------|
| Main | `src/main/index.ts` | **injeca** 装配 → `injeca.start()` |
| Renderer | `src/renderer/main.ts` → `App.vue` | Vue 3 + Pinia + **Hash** 路由 |

产物入口：`package.json` → `"main": "./out/main/index.js"`。

开发：`pnpm dev:tamagotchi`（根脚本）或 `pnpm -F @proj-airi/stage-tamagotchi dev`（`electron-vite dev`）。

## Defines / URL 模式

| Define | 含义 |
|--------|------|
| `RUNTIME_ENVIRONMENT='electron'` | 与 Web 区分运行时 |
| `URL_MODE` | dev=`server` · prod=`file` |

另有独立 HTML：`beat-sync.html` + 专用 preload（**不是** Vue Router 的 `#/beat-sync`）。

## 路由合并（与 Web 不同）

`VueRouter` 的 `routesFolder`：

1. **`packages/stage-pages/src/pages`**（先扫），并 **exclude** 一批由本端覆盖的页
2. **`src/renderer/pages`**（后扫，同名路径以本端为准）

全局再 exclude：`**/components/**`。

### stage-pages 被 exclude 的路径（桌宠本地有对应页）

| 被排除的包内页 | 含义 |
|----------------|------|
| `settings/account` · `connection` · `data` · `models/index` | 桌面账号 / 连接 QR / 数据 / 模型（含 Godot） |
| `settings/system/general` · `modules/mcp` · `settings/index` | 系统与 MCP、设置首页 |
| `devtools/index` | 桌面 Devtools 入口 |

**不要**当成「功能缺失」——实现在 `src/renderer/pages/...`。

对比 Web：`stage-web` 通常 **本端 pages 在前**、且 **没有** 这批 exclude。细节以各端 vite/electron.vite 为准。

## Layouts

`layoutsDirs` 顺序：

1. `src/renderer/layouts`（本端优先）
2. `packages/stage-layouts/src/layouts`

本端有：`default.vue` · `stage.vue` · `settings.vue`（settings 常带 Electron `TitleBar`；stage 多为裸 `RouterView`）。

包内独有、本端未覆盖的布局（如 `plain` / `home`）仍来自共享包——about / notice / onboarding 等常挂 `plain`。

注意：Layouts 插件的 `pagesDirs` **只扫本端** `src/renderer/pages`，与「路由合并了 stage-pages」不完全同一集合；学设置/devtools 时以实际路由与文件为准。

## Renderer 路由模式

`createWebHashHistory()` —— 窗口 URL 形如 `.../index.html#/chat`。

主窗加载常不带显式 hash（落在 `/`）；其它窗用 `withHashRoute` 一类助手拼 `#/settings` 等。chat-sync 角色解析会读 `location.hash`，见 [多窗同步](./多窗同步.md)。
