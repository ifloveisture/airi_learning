# 记忆检索

> 串：独立 Agent（**仅 Telegram**）读未读时，如何从历史里捞「相关」片段。
> Satori 无向量回忆。Stage 产品长期记忆仍为 WIP（`memory-pgvector` 空壳；设置页占位）——本页公式不适用于 Stage。

## 触发位置

`read_unread_messages`（`services/telegram-bot/.../actions/read-message.ts`）：

```text
未读消息 → 逐条 embedding
  → findRelevantMessages(botId, chatId, embeddings, excludeIds)
  → 与「最近 N 条」一并填进 action 结果模板
  → 清空该聊 unreadMessages
```

排除集：当前未读 id + 已经取出的最近消息 id，避免重复塞上下文。

## 评分公式

源码：`services/telegram-bot/src/models/chat-message.ts` → `findRelevantMessages`

相似度（pgvector 余弦距离转相似）：

```text
similarity = 1 - cosineDistance(stored_vector, query_embedding)
```

向量列由 `EMBEDDING_DIMENSION` 选择：`1536` / `1024` / `768`（HNSW `vector_cosine_ops`）。

时间相关（约 30 天线性衰减，SQL 原样）：

```text
time_relevance = 1 - (now_ms - created_at) / 86400 / 30
```

综合分：

```text
combined_score = 1.2 * similarity + 0.2 * time_relevance
```

| 权重 | 项 | 意图 |
|------|----|------|
| 1.2 | 语义相似 | 主信号 |
| 0.2 | 时间新鲜 | 轻微偏向较新消息 |

## 过滤与截取

| 规则 | 值 |
|------|----|
| 相似门槛 | `similarity > 0.5`（先滤再排序） |
| Top-K | `limit(3)`，按 `combined_score` 降序 |
| 上下文窗 | 命中消息前后各 **5** 条（`contextWindowSize = 5`） |

对每个未读 embedding 各跑一遍上述查询，再拼进提示。
批量回填历史向量：`pnpm -F @proj-airi/telegram-bot script:embed-chat`。

## 和调度的关系

```text
[Agent调度] loop
  → Action = read_unread_messages
  → 本篇检索
  → LLM 下一轮 imagineAnAction / send_message
```

没有过门槛的向量命中时，仍可能只靠「最近消息」回复——调试「不记得」时先看：embedding 是否写入、维度是否匹配、`similarity` 是否总 &lt; 0.5。
