# 编排与上下文

> 串：任意入口（文本 / 语音 flush / Channel `input:text`）→ 稳定的一轮 LLM。
> Store 拆分见 [聊天编排](../角色对话/聊天编排.md)。

## 1. FIFO 入队 + generation 作废

源码：`packages/core-agent/src/runtime/chat-orchestrator-runtime.ts`（`createQueue` from `@proj-airi/stream-kit`）

```text
ingest(text, options)
  → 捕获当前 sessionId + generation
  → 入 FIFO
  → 串行执行：append user → compose → stream → append assistant → persist
```

关键判定：

| 情况 | 行为 |
|------|------|
| 队列中尚未开始的 send 被 cancel | 直接 reject，不跑 LLM |
| 出队时 `generation` 已变（会话重置 / 新世代） | 视为 stale，reject，不跑 LLM |
| 正在跑的一轮 | 队列后方等待（单通道串行） |

产品入口：`useChatOrchestratorStore().ingest`（`packages/stage-ui/src/stores/chat.ts`）。
桌宠多窗：follower 经 sync **请求** authority 侧 ingest，避免双编排——见 [多窗同步](../多端应用/桌宠端/多窗同步.md)。

## 2. 流式 UI 刷新粒度

同文件：`STREAMING_UI_FLUSH_CHUNK_SIZE = 24`

前台 `streamingMessage` 按约 24 字符粒度 patch，平衡流畅度与重绘成本（细节在 runtime + `stream-store`）。

## 3. 上下文历史：400 环形裁剪

源码：

- `packages/core-agent/src/runtime/context-registry.ts`（`historyLimit` 默认 **400**）
- `packages/stage-ui/src/stores/chat/context-store.ts`（显式 `CONTEXT_HISTORY_LIMIT = 400`）

```text
每次写入 history
  → 与既有条目合并
  → slice(-historyLimit)   # 只留最新 400 条
```

桶策略（registry）：

| 策略 | 含义 |
|------|------|
| replace-self | 同桶先清再写 |
| append-self | 同桶追加 |

超限时**静默丢最旧**，不是报错。学「为什么旧上下文不见了」先查这里，再查会话消息表 / 云同步。
